# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project

SummaRace is an **offline Android reading game** (Unity 6 / URP 17.4.0, portrait, new Input System) teaching Grade-4 learners to summarize stories via the **SWBST framework** (Somebody·Wanted·But·So·Then). It is a **college thesis instrument** — 40 learners will use it across 10 sessions and be compared to a control group.

**Read the docs in `Documentation/` before making design decisions:**
- `SummaRace_Project_Brief.md` — orientation (read first)
- `SummaRace_Final_GDD.docx` — design bible; all decisions D1–D18 are LOCKED
- `SummaRace_Technical_Design_Document.md` — implementation spec (scenes, scripts, events, race system)
- `SummaRace_Build_Guide.md` — build order (phases A–J)
- `SummaRace_Asset_Requirements_List.md` — asset bill of materials
- `SummaRace_Finalization_Plan.md` — the remaining work to a study-ready build (**the live plan**; don't restate it elsewhere)
- `AssetGeneration/README.md` — ten world recipes, weather/mood, collectible skins (§1–3) + every asset still to be produced with target path, size and priority (§4)
- `Documentation/Mockups/1..27.png` — validated prototype screens (visual target). Live demo: https://tdrx44.csb.app/

**Non-negotiables:** 100% offline (no networking/ads/analytics), never punish the learner (wrong answers never block; "caught" is friendly, never game-over), content is JSON data never code, all 30 stories flow through one reusable engine.

## Architecture (implemented — follow these patterns)

- **Singletons** (`_Game/Scripts/Core/`): `Bootstrapper` (Boot scene) creates `[Core]` GameObject with `GameManager`, `AudioManager`, `SaveManager`, `SceneLoader` (DontDestroyOnLoad). `EventBus` is static pub/sub; event payloads in `Core/GameEvents.cs` (catalog in TDD §8).
- **Features never call each other** — raise EventBus events + read `GameManager` state. Scene flow only via `SceneLoader.Instance.Load(SceneNames.X)`.
- **Constants only** (`_Game/Scripts/Constants/`): `SceneNames`, `AudioKeys`, `PrefKeys`, `GameRules` (all tuning numbers), `GameText` (all learner-facing strings). Never hard-code a scene name, audio key, gameplay number, or UI string.
- **Content pipeline** (`_Game/Scripts/Data/`): `StoryLoader.Load("s01_easy")` reads `Resources/Stories/<id>.json` → validated `StoryData`. Add a story = add a JSON, zero code. `Data/StoryIds` owns the `sNN_<difficulty>` convention — resolve an id through it, never by string-building, so StorySelect and SessionMap can't disagree. The 30 JSONs are **generated** by `Tools/StoryPipeline/` (see its README) — edit content there, not in the files.
- **Persistence + research data** (`Core/`): `SaveManager` (profiles, per-learner `.jsonl` logs, `ExportLogs`, `DeleteAllData`), `SessionLogService` (one `SessionLog` per play-through, built from EventBus traffic only), `TeacherGate` (salted PIN hash, session unlock). Never store a raw PIN; never log anything that leaves the device.
- **Audio**: clips live in `Assets/_Game/Resources/Audio/` named exactly per `AudioKeys` (e.g. `sfx_correct.ogg`); `AudioManager.Instance.PlaySfx(AudioKeys.SfxCorrect)`. Swap a sound = replace the file. Raw Kenney packs in `Assets/Audio/Kenney/` are the source library.
- **Every scene controller** null-checks `GameManager.Instance`/`CurrentStory` and falls back to `StoryLoader.Load("s01_easy")` so any scene can be played directly in-editor (TDD §13).
- **Naming**: PascalCase scripts/scenes/methods, `_camelCase` privates, `[SerializeField] private` over public, snake_case asset files, namespaces `SummaRace.<Layer>` matching folders.
- **Third-party packs go in `Assets/Plugins/`** (13 packs there now). Design reference for UI skin: `Plugins/Hyper_Casual_UI/Scenes/Demo_Game_UI`. Fonts: `Assets/Art/Fonts/` Fredoka (headings) + Nunito (body) — make TMP assets in Phase F. Characters + Mixamo clips (all Humanoid): `Assets/Art/Characters/`.

## Working with the Unity Editor (MCP)

This project has **MCP For Unity** (`com.coplaydev.unity-mcp`) installed. When a Unity Editor instance is connected, prefer the `mcp__UnityMCP__*` tools over editing serialized assets by hand:

- **Read editor/project state via MCP resources**, then mutate via tools — check state before changing it.
- Scenes/objects: `manage_scene`, `manage_gameobject`, etc. — raw `.unity`/`.prefab` YAML edits break GUID/fileID references. Complex scene builds work well via `execute_code` (C#6-ish subset; use `UnityEngine.Object.DestroyImmediate`, wire `[SerializeField]` fields via `SerializedObject`).
- C#: write files, then refresh with compile and verify the type exists in `Assembly-CSharp` before building scenes that reference it.
- Do **not** run Unity CLI `-batchmode` while the Editor is open — it locks the project.
- **Gotchas learned:**
  1. If a new `.cs` validates clean but its type never appears in `Assembly-CSharp` (compile time ~1ms, file missing from CompilationPipeline sources), Unity's incremental compiler has stale tracking → delete the `.cs`+`.meta`, refresh, re-add the file fresh.
  2. **`refresh_unity` does NOT compile** (it returns `compile_requested: false`). Follow it with `CompilationPipeline.RequestScriptCompilation()` or you will reflect over stale types and believe a wrong result.
  3. **`execute_code` runs as a method body** — `using` directives are a compile error there. Fully qualify (`System.Text.StringBuilder`, `UnityEditor.AssetDatabase`).
  4. **Trash Dash ships its own `GameManager` in the global namespace**, which outranks a using-directive, and an alias named `GameManager` is illegal for the same reason (CS0576). Use `using Core = SummaRace.Core;` and qualify.
  5. **Overlay UI cannot be judged in the Editor's game view** — it is landscape, the game is portrait-locked. Render the canvas through an offscreen camera into a RenderTexture at 720×1280 for a true portrait check. Every P2b/P3b layout bug (overflowing board, duplicated "Enter PIN" label, indistinguishable avatars, low-contrast pill) was caught this way and none of them was visible in code.
  6. **Kit sprites can be BAKED showcase art** — `Hyper_Casual_UI/Sprites/GameUI/Level.png` has "Level 23", "Score 232,00", stars and a lock *drawn into the image*, so a number layered on top stacks onto someone else's UI. **Look at any kit sprite before using it**; several also ship with broken importers (not Sprite type, or Multiple mode with no rects).
  7. Play mode pauses without Editor focus (Run In Background off) — the MCP bridge stalls; have the owner click Unity/press Play. A `Time.timeScale=0` seen while MCP-driving is usually this, not a bug.
  8. **Unity does not run `Awake`/`OnEnable` in edit mode**, so singleton `Instance`s stay null and `SessionLogService` never subscribes. Invoke the lifecycle methods by reflection or an edit-mode test silently proves nothing — that cost one wrong result in P3a.
  9. Asset-store imports land in `Assets/` root — move to `Plugins/` via `AssetDatabase.MoveAsset` (or move file+`.meta` together on disk), never a bare file move.

## Code layout & assemblies

No `.asmdef` files: runtime → `Assembly-CSharp`, editor-only (`Editor/` folders) → `Assembly-CSharp-Editor`. Introduce asmdefs before adding test assemblies or if compile times grow.

## Rendering

⚠️ **The two-tier model below is NOT what currently runs — verify before relying on it.** Measured 2026-08-05: every quality level has `customRenderPipeline: {fileID: 0}` and `GraphicsSettings.m_CustomRenderPipeline` points at **`Assets/RenderingPipeline.asset` (Trash Dash's)** with `Assets/UIRenderer.asset` as its renderer. `Mobile_RPAsset`/`Mobile_Renderer` and `PC_RPAsset`/`PC_Renderer` are **assigned to nothing**, so every tuning decision recorded for them is dead. Consequences on the 2GB floor device, in cost order: `renderScale` is **1.0**, not Mobile's 0.8 (that alone is ~36% of fragment cost); main-light shadows on with a **2048 map and 4 cascades** at 50m (four extra passes on a tiler); `m_IntermediateTextureMode: Always` on UIRenderer forces an intermediate colour target instead of direct-to-backbuffer. Do NOT simply reassign the Mobile asset — the whole F26–F42 race look was built and playtested against *their* pipeline (curved/unlit materials), so switching is a visual change that needs a playtest, not a config tidy. Note also RAM is the real pressure, not polygons: the full Daytime theme is only ~80k verts, while ~36MB of Vorbis music is set **DecompressOnLoad** and expands to raw PCM.

Two URP tiers exist as assets (Project Settings → Quality/Graphics): `Assets/Settings/PC_RPAsset` + `PC_Renderer`, `Mobile_RPAsset` + `Mobile_Renderer`. If they are ever wired up, apply renderer/shader/post changes to **both** (or deliberately tier-gate). Device floor: 2GB Android 8, 30fps in race, APK ≤ 300MB. Android: IL2CPP, ARM64, min API 26, portrait locked.
